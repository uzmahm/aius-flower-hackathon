Disclosure Ledger

Four agents book a surprise birthday dinner. Each one holds its owner's real calendar, budget ceiling and medical record, and none of them states any of it. The planner finds the answer by asking yes/no questions.

Why a rejection is not a disclosure

An earlier version of this protocol opened by asking everyone for their availability and their price band. Both are the sensitive thing itself, only coarsened — a band is the budget, a set of free hours is the calendar. Neither is asked any more, because a bit answers the same question and a bit can be denied.

The boundary

The runtime, not the prompt, sets the topology: a SuperNode is granted push_reply_message and nothing else, so no guest agent can address another. Every bit crosses one of these four edges. Click a node to follow it through the run.

Every round, and what it costs

Rounds are ordered because the protocol is. Each one declares the exact fields a reply may contain, so its cost is known before any model runs — a round of offers is priced the same whatever the answers are.

The search

The planner is working blind. It proposes fully specified offers — this venue, this hour, this price — and learns only which ones survive. Nothing tells it why an offer died, so it re-proposes around the pattern of accepts, the way twenty questions narrows a word.

Held local versus disclosed

The field names on the left never left their machine. This page was built from a trace that contains their names and not their values. On the right is the complete set of everything that did travel.

What the guard refuses

Replies a model might plausibly produce, run against the live policy. Four of these are an agent being helpful — attaching the reason, the budget, the calendar clash — which is exactly how private data escapes in practice. None of these verdicts depends on what a model decides to do: a reply that fails validation never becomes a message.

Run it yourself

No federation, no model

cd dinner-planner
PYTHONPATH=. python -m agent.selfcheck
PYTHONPATH=. python dryrun.py

The first runs the guard cases above. The second runs the whole protocol against simulated guests whose private rules read a real calendar, budget and dietary record, then asserts that no round ever asked for an attribute and that the guest of honour was never told.
